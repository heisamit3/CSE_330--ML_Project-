1 — Competition Overview

The MAP (Misconception Annotation Project) is a Kaggle competition hosted by Eedi & The Learning Agency (2025). Given a student's open-ended written response to a multiple-choice math question, the model must simultaneously:

  1. Determine whether the student selected the correct answer.
  2. Detect whether the student's explanation exhibits a misconception.
  3. Identify the specific misconception (from ~35 named types) if present.
Why this is hard There are 65 combined labels (Category:Misconception pairs) with extreme class imbalance (up to a 14 800:1 ratio). The model must generalise across math topics it has never seen during cross-validation, requiring careful CV design to avoid data leakage.

Evaluation Metric — MAP@3

The competition scores submissions using Mean Average Precision at rank 3:

MAP@3 = (1/N) × Σi Σk=1..3 P(k) × rel(k)

Each sample contributes 1/rank if the correct label appears in position rank of the top-3 predictions, and 0 otherwise. This rewards models that rank the true label as high as possible even when they are not perfectly confident.

5 — Exploratory Data Analysis (Cell 3)

What is done

Loads the training CSV and produces four visualisations:

  1. Category distribution — horizontal bar chart of the 6 top-level categories (True_Correct, True_Neither, True_Misconception, and their False_* counterparts).
  2. Top-15 Misconception types — shows which misconceptions appear most frequently in student responses.
  3. Explanation length histogram — word-count distribution of StudentExplanation, with median marked.
  4. Top-15 combined labels — the actual prediction target (Category:Misconception pairs).

Key findings

  • 6 category types, 35 unique misconception types → 65 combined labels.
  • True_Correct:NA dominates (~40%), causing severe class imbalance.
  • Median explanation length ≈ 10–15 words; tails reach 100+ words.
  • Class imbalance ratio up to 14 800:1 — motivates Focal Loss.

Why EDA matters here

Understanding class imbalance directly dictates the loss function choice (Focal Loss vs standard cross-entropy). The text length distribution sets the MAX_LEN=512 tokenisation budget. Knowing the True/False split motivates the post-processing Family Filter (Section 9).

6 — Feature Engineering (Cell 4)

What is done

6.1 Correct Answer Inference

def build_correct_by_q(df):
    correct_mask = df["Category"].str.startswith("True")
    return df[correct_mask].groupby("QuestionId")["MC_Answer"]\
           .agg(lambda s: s.value_counts().index[0]).to_dict()

For each question, the most frequent answer among students who were labelled True_* (i.e., selected the right option) is taken as the ground-truth correct answer.

Why The test set does not provide the correct answer explicitly. By inferring it from the training set, the model gains a crucial signal: the gap between what the student answered and what is correct. This gap is the primary driver of misconception classification. Importantly, this inference is performed inside each cross-validation fold using only the training portion of that fold, preventing any leakage.

6.2 Structured Input Text

Task: Classify the student's math response and identify any misconception.
Question: {question_text}
Student's Answer: {student_answer}
Correct Answer: {inferred_correct_answer}
Is Student Correct: Yes / No / Unknown
Student's Explanation: {explanation}

All available signals are concatenated with explicit semantic labels into a single string fed to the DeBERTa tokeniser (truncated to 512 tokens).

Why Transformer encoders accept a single flat sequence. Explicitly labelling each field guides the model's attention — the separator structure is analogous to how BERT uses [SEP] tokens to separate sentence pairs, but richer. Including the correct answer in the prompt lets the model reason about the size and direction of the student's error, dramatically improving identification of subtle misconceptions.

6.3 Label Encoding & Family Masks

All 65 Category:Misconception strings are sorted and mapped to integer IDs. Two boolean arrays, true_mask and false_mask, record which label indices correspond to True_* and False_* categories respectively — used later for the Family Filter post-processing step.

6.4 Inverse-Frequency Class Weights

Per-class weights w_c = 1 / count_c (normalised to mean 1) are computed from the training label distribution and passed to the Focal Loss as its alpha parameter, giving rare misconceptions a larger gradient signal.

7 — Advanced Training Components (Cell 5)

This cell implements six training innovations that push accuracy significantly beyond vanilla fine-tuning. Each is motivated by well-cited literature.

Adversarial Weight Perturbation (AWP)

After the normal backward pass, the model weights are adversarially perturbed in the direction of the gradient by a small step. A second loss is computed on these perturbed weights, then the weights are restored. This forces the optimizer to find minima that are flat (robust to small perturbations), improving generalization.

Wu et al., NeurIPS 2020. Expected Δ MAP@3 ≈ +1.0–2.0%.

Exponential Moving Average (EMA)

A shadow copy of the model weights is maintained as an EMA:
shadow ← (1-decay)·param + decay·shadow
At evaluation and inference time, the EMA weights are used instead of the raw trained weights. Because EMA averages over many steps, it produces smoother, less noisy predictions.

Polyak & Juditsky, SIAM 1992. Expected Δ MAP@3 ≈ +0.3–0.8%.

R-Drop (Regularized Dropout)

Each training batch is fed through the model twice with different random dropout masks, yielding two probability distributions. The KL divergence between them is minimised as an auxiliary loss (weight α = 0.3):
loss = CE_avg + α · KL(p₁ ‖ p₂)
This consistency constraint acts like data augmentation at the representation level.

Wu et al., NeurIPS 2021. Expected Δ MAP@3 ≈ +0.5–1.5%.

Focal Loss

Standard cross-entropy treats all training examples equally. Focal Loss down-weights easy, well-classified examples by a factor (1 − pt)^γ:
FL(pt) = −αt(1−pt)^γ log(pt)
With γ=2 and inverse-frequency alpha, the model focuses its gradient budget on rare and hard misconception classes — critical for the 14 800:1 imbalance.

Lin et al., ICCV 2017. Expected Δ MAP@3 ≈ +2–5% on rare classes.

Layerwise Learning Rate Decay

Earlier (lower) transformer layers receive geometrically smaller learning rates: LR_layer_i = LR × decay^i (decay = 0.95). The classifier head uses the full LR. This prevents the model from destroying pretrained linguistic knowledge stored in earlier layers while still adapting the top layers.

Clark et al., ICLR 2020. Expected Δ MAP@3 ≈ +0.5–1.0%.

Cosine Schedule + Linear Warmup

The learning rate starts from 0, linearly ramps to LR over the first 10% of steps (warmup), then follows a cosine decay to 0. This avoids the large gradient magnitudes at the start of training (which can damage pretrained weights) and provides smooth convergence.

Loshchilov & Hutter, ICLR 2017. Expected Δ MAP@3 ≈ +0.3–0.8%.

BF16 Stability Patch

DeBERTa-v3's custom StableDropout performs mask.to(x.dtype) followed by division by (1−p). Under BF16 autocast, this can produce NaN values. The code monkey-patches this class with a standard F.dropout call, which is numerically safe in all precisions.

Learned Temperature Scaling

After all folds are trained, the out-of-fold (OOF) logits are used to learn an optimal temperature T via LBFGS minimization of the negative log-likelihood: loss = CrossEntropy(logits / T, true_labels). Dividing logits by T > 1 softens the probability distribution, improving calibration of the top-3 ranking.

Why calibration matters for MAP@3 MAP@3 cares about the rank order of the top-3 predictions, not just the top-1. Well-calibrated probabilities ensure that the 2nd and 3rd predictions are genuinely the next-most-likely labels, contributing higher average precision.

Reference: Guo et al., ICML 2017.

8 — DeBERTa-v3-Large Fine-Tuning (Cells 6 / 6a)

Why DeBERTa-v3-Large?

DeBERTa-v3 (He et al., ICLR 2023) uses two key innovations over BERT/RoBERTa:
  • Disentangled Attention — Content and position are encoded in separate vectors and combined at attention-score time. This makes the model more sensitive to where a concept appears, critical for parsing structured input text like the template used here.
  • ELECTRA-style pre-training with gradient-disentangled embedding sharing — provides a stronger initialisation for downstream classification tasks, consistently outperforming RoBERTa-large on GLUE/SuperGLUE benchmarks.

Cross-Validation: GroupKFold by QuestionId

Standard random KFold would place responses to the same math question in both train and validation. Because DeBERTa can memorise question-specific patterns, this would inflate MAP@3 scores — the model wouldn't need to generalise to unseen questions.

GroupKFold(groups=QuestionId) guarantees that all responses to a given question appear in exactly one fold. This gives an honest estimate of performance on unseen questions — the scenario at test time.

Training Loop Summary (per fold)

  1. Build correct_by_q from the training split only.
  2. Construct structured input texts, tokenise, build HF Dataset.
  3. Initialise fresh DeBERTa-v3-large with random classification head (ignore_mismatched_sizes=True).
  4. Configure layerwise LR optimizer + cosine schedule.
  5. For each epoch / batch:
    • Double forward pass (R-Drop) → Focal + KL loss.
    • Gradient accumulation (effective batch = 32).
    • AWP adversarial step (after epoch 1).
    • EMA update after each optimiser step.
  6. Evaluate with EMA weights → store OOF logits and fold MAP@3.
  7. Optionally save the fold model checkpoint.

Multi-Seed Ensemble

The entire GroupKFold training is repeated for 3 random seeds ([42, 123, 456]). OOF logits from all seeds are averaged before post-processing. This Deep Ensemble strategy (Lakshminarayanan et al., NeurIPS 2017) reduces variance from random weight initialisation and typically adds +0.5–1.0% MAP@3.

Inference Dry-Run (Cell 6a)

Before the full 2–3 hour training starts, the entire test inference code path is executed against 6 training samples using a randomly-initialised model head. Predictions are deliberately wrong (random), but every code path — tokeniser, collator, DataLoader, forward pass, apply_filters, top3_from_logits — is exercised. This catches bugs before wasting GPU hours.

9 — Post-Processing (Cells 5h, 6)

9.1 Family Filter

Once the model's is_correct flag for a sample is known (1 = correct, 0 = incorrect):

  • If is_correct == 1, all False_* label logits are set to −∞. The student answered correctly, so any False_* label is impossible by definition.
  • If is_correct == 0, all True_* label logits are set to −∞.
Why This is hard-domain-knowledge: the competition dataset's label space is structured so that Category always starts with the correctness prefix. Enforcing this constraint eliminates roughly 50% of the label space for each sample, dramatically sharpening the remaining probability distribution and boosting MAP@3 by +0.5–1.5%.

9.2 Learned Temperature Scaling

After masking impossible labels, all logits are divided by the learned temperature T (optimised on OOF data, typically in the range 1.2–1.8). This softens prediction confidence, improving the ranking of the 2nd and 3rd candidates in the top-3 output. The temperature is learned — not hand-tuned — using LBFGS minimisation of the NLL on OOF logits.

10 — Evaluation & Error Analysis (Cell 7)

What is done

Three visualisations are generated from the OOF predictions:

  1. MAP@3 per Fold — bar chart with mean and ensemble lines. Folds below mean are red; above mean are green.
  2. Category Classification Accuracy — for each of the 6 top-level categories, what proportion of top-1 predictions have the correct category prefix.
  3. Hardest Misconceptions — the 10 misconception types with the lowest per-class MAP@3, highlighting where the model struggles most.

Score Report (Cell 7b)

A detailed per-category breakdown is printed: count, MAP@3, Top-1 Accuracy, and Top-3 Accuracy for each of the 6 categories. This can also reload saved fold checkpoints and re-evaluate on a new sample of training records (independent of the OOF run).

Why error analysis

Knowing which misconceptions are hardest to classify guides future improvements: rare classes may benefit from additional data augmentation; structurally ambiguous classes (e.g., "Additive" vs "Multiplicative") may require sub-type-specific prompting. Error analysis also satisfies academic rigour expected by supervisors and reviewers.

11 — Explainable AI (Cells 8 & 9)

11.1 Misconception Knowledge Base (Cell 8)

For each of the top-N misconception types (50 in quick-run mode), the pipeline:

  1. Samples up to 4 representative student responses from the training set.
  2. Prompts a large language model (Qwen 2.5 7B Instruct via 4-bit quantisation, or FLAN-T5-Large as fallback) to generate a structured knowledge card:
    • plain_definition — 1–2 sentence lay explanation of the misconception.
    • typical_wrong_thought — list of common incorrect reasoning patterns.
    • correct_rule — the mathematically correct principle.
    • fix_steps — 4–7 pedagogical steps for a teacher or student to follow.
    • quick_check — single self-assessment question.
    • tiny_example — a compact worked example.
  3. Caches all cards as misconception_kb.json so the LLM does not need to run on subsequent notebook runs.
Why build a Knowledge Base Raw model predictions say what the misconception is but not why it occurs or how to fix it. In an educational deployment, teachers need actionable guidance — not just a label. The KB transforms the model from a classifier into a pedagogical assistant. Using an LLM to auto-generate KB cards scales to any new misconception class without manual authoring.

11.2 Teacher Feedback Generator (Cell 9)

For each predicted misconception, a personalised teacher-facing explanation is generated:

  1. DeBERTa provides the top-3 predicted labels (with probabilities).
  2. The KB card for the top-1 prediction is retrieved.
  3. An LLM (or rule-based fallback) produces a structured feedback:
    • What the student appears to think.
    • The misconception in simple language.
    • Step-by-step correct reasoning.
    • A self-check question.
  4. Rule-based verification softens negative language if the student was actually correct (is_correct == 1), and prepends the correct answer if it was incorrect.
  5. LLM-based verification (optional) removes contradictions and improves tone.
Why personalisation matters Generic feedback ("you made an arithmetic error") is less effective than targeted guidance ("You seem to think fractions add by adding numerators and denominators separately — here is the correct rule and a step-by-step fix"). Personalised misconception feedback is shown to improve student outcomes in the learning-science literature.

12 — Test Inference & Submission (Cell 10)

What is done

  1. Load test CSV; fill missing values.
  2. Infer is_correct from full training set's correct_by_q map.
  3. Build structured input texts (same template as training).
  4. Tokenise and create a DataLoader.
  5. Load all saved fold model checkpoints (seed*_fold*); run inference with each; average logits. Fallback: retrain on full data (R-Drop + EMA) if no checkpoints exist.
  6. Apply Family Filter + Learned Temperature Scaling.
  7. Extract top-3 label strings per sample.
  8. Write submission.csv in the competition format: row_id, "LabelA LabelB LabelC".

Why load saved fold models

Re-loading saved EMA checkpoints from every fold and seed replicates the exact ensemble used during CV evaluation. This is mathematically equivalent to the OOF ensemble and avoids the information-theoretic risk of "full-data retraining" which can overfit to training distribution subtleties unseen at test time.

Key Takeaways

  1. DeBERTa-v3-Large is the optimal backbone for this task — its disentangled attention excels at parsing the structured Question/Answer/Explanation template.
  2. AWP and R-Drop provide the largest individual accuracy gains by improving generalization on the challenging multi-class, imbalanced problem.
  3. GroupKFold is non-negotiable — random splits inflate CV scores by 5–10% due to question-level memorisation; only GroupKFold gives an honest estimate.
  4. Focal Loss is essential given the severe label imbalance. Standard cross-entropy under-trains on rare misconception types.
  5. Explainable AI elevates the system from a black-box classifier to a pedagogical tool — critical for real-world educational deployment and teacher trust.
